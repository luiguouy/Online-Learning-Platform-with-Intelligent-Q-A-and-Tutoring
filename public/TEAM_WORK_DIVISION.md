# AI驱动的在线学习智能答疑辅导平台（RAG课程知识库）
## 4人小组详细分工与项目协同实施方案

> **项目名称**：AI 驱动的在线学习智能答疑辅导平台（RAG 课程知识库）  
> **团队规模**：4 人（本科生软件工程 / 计算机专业课程设计团队）  
> **设计基调**：轻量实用、高内聚低耦合、避免过度工程化、保障演示闭环  
> **核心交付**：Java 全栈架构、RAG 课件知识库检索、流式打字机答疑、知识点深度解析、问答记录持久化、教师后台管理

## 二、 成员细粒度分工计划清单 (WBS)

### 2.1 成员 A（组长 / AI 与 RAG 核心架构师）
- **核心任务**：
  1. **工程骨架搭建**：创建 Spring Boot 3.x 统一工程，集成 Maven 依赖管理，制定代码分支规范。
  2. **RAG 向量流水线**：
     - 基于 LangChain4j 或 Spring AI，封装课件文档提取解析器（支持 PDF、Markdown、TXT）。
     - 实现智能文本切块逻辑（Recursive Chunking: 400 字符分块，50 字符重叠）。
     - 集成 Text Embedding 模型（如通义千问 text-embedding-v3 或本地轻量向量模型）。
     - 接入轻量向量库（Chroma Docker 单机版 或 LangChain4j 内置向量存储）。
  3. **智能答疑检索增强**：
     - 实现根据 `courseId` 元数据过滤的 Top-K 向量相似度检索。
     - 设计专业学科助教 Prompt 模板（注入上下文、防幻觉、严格格式约束）。
     - 编写 Server-Sent Events (SSE) 流式返回控制器 `/api/qa/chat/stream`。
  4. **知识点深度解析生成**：
     - 编写结构化 Prompt，生成指定知识点的核心概念、难点解析及 3 道自测选择题。

### 2.2 成员 B（后端业务与数据库工程师）
- **核心任务**：
  1. **数据库模型设计**：
     - 设计并编写 MySQL 建表脚本：`sys_user`（用户表）、`course`（课程表）、`course_document`（课件文档表）、`qa_session`（问答会话表）、`qa_record`（问答明细表）、`course_knowledge_point`（知识点表）。
  2. **基础业务代码开发**：
     - 基于 MyBatis-Plus 实现通用 BaseMapper、IService 及 CRUD 接口。
     - 集成 Sa-Token 轻量级权限框架，实现学生与教师的角色鉴权与 Token 校验。
  3. **课程与文件元数据管理**：
     - 实现本地或 MinIO 文件上传接口，校验文件大小与扩展名。
     - 维护文档处理状态机：`PENDING(待处理)` -> `PROCESSING(切块中)` -> `SUCCESS(已构建索引)` -> `FAILED(失败)`。
  4. **问答历史与评价系统**：
     - 实现问答记录的异步持久化（记录学生提问、模型答案、知识库出处 JSON 片段）。
     - 实现学生点赞/点踩反馈接口、历史会话分页查询。
     - 提供教师后台数据统计 API（各课程问答量、高频提问统计）。

### 2.3 成员 C（前端开发工程师 - 学生交互核心）
- **核心任务**：
  1. **学生前台界面架构**：
     - 搭建 Vue 3 + Vite + Element Plus + Pinia 前端基础脚手架。
     - 配置前端路由系统与全局状态（当前选中的课程、当前对话 Session）。
  2. **核心流式问答工作台**：
     - 对接后端 SSE 接口，实现打字机平滑流式吐字动画与光标闪烁效果。
     - 集成 Markdown 解析库（支持标准 Markdown 语法、表格、任务列表）。
     - 集成 `highlight.js` 实现代码高亮与一键复制功能。
     - 集成 `KaTeX` 支持数学与算法公式渲染（适用于理工科课程）。
  3. **知识溯源看板 (Grounding Drawer)**：
     - 回答气泡底部渲染“参考资料 (X 处)”标签。
     - 点击弹窗或右侧抽屉，展示命中的课件片段详情（包含课件名、分块序号及相关度得分）。
  4. **知识点自测卡片视图**：
     - 制作知识点卡片展开折叠、自测题答题交互与答案即时校验。

### 2.4 成员 D（前端开发与质检工程师 - 教师后台与文档）
- **核心任务**：
  1. **教师后台管理工作台**：
     - 实现课程管理界面（创建课程、设置课程简介、修改状态）。
     - 实现课件知识库管理界面（拖拽上传课件、查看解析切块进度条、手动重新构建索引）。
  2. **问答监察与答案修正系统**：
     - 开发所有学生提问日志表格，支持按课程、时间、关键词筛选。
     - 实现教师“人工纠偏”功能：教师可直接修改某条 AI 回答，保存为权威标准答案。
  3. **数据可视化看板**：
     - 集成 ECharts 渲染学情分析图表（每日提问走势折线图、课程问答占比饼图）。
  4. **全链路测试与答辩成果物**：
     - 负责 Postman / 前后端端到端黑盒测试，记录 Bug 缺陷清单并推动修复。
     - 准备高质量测试课件数据集（如精选 3~5 篇经典计算机教材章节 PDF）。
     - 编写《软件需求规格说明书》、《系统详细设计文档》及最终答辩汇报演示 PPT。

## 三、 前后端与 AI 协同接口矩阵 (API Matrix)

| 接口名称 | 接口路径 | 请求方式 | 提供方 (责任人) | 调用方 (责任人) | 核心联动数据 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **用户登录** | `/api/auth/login` | `POST` | 成员 B | 成员 C & D | 账号密码 -> Token & Role |
| **课程列表** | `/api/course/list` | `GET` | 成员 B | 成员 C & D | 课程列表与激活状态 |
| **课件上传** | `/api/teacher/docs/upload` | `POST (Form)` | 成员 B & A | 成员 D | 上传课件并触发异步切块 |
| **索引重构** | `/api/teacher/docs/{id}/reindex` | `POST` | 成员 A | 成员 D | 重新计算 Embedding 向量 |
| **智能答疑 (SSE)** | `/api/qa/chat/stream` | `GET (SSE)` | 成员 A | 成员 C | `question`, `courseId` -> 流式片段与出处 |
| **会话历史** | `/api/qa/sessions` | `GET` | 成员 B | 成员 C | 历史会话列表与对话记录 |
| **点赞评价** | `/api/qa/records/{id}/feedback`| `POST` | 成员 B | 成员 C | `recordId`, `status(1/-1)` |
| **知识点生成** | `/api/knowledge/generate` | `POST` | 成员 A | 成员 C | 知识点名称 -> 结构化考点解析 |
| **问答审查修正** | `/api/teacher/qa/correct` | `POST` | 成员 B | 成员 D | `recordId`, `teacherAnswer` |

## 四、 5周推进路线图与关键里程碑 (Timeline)

```text
第 1 周 [基础对齐] ──> 第 2 周 [骨架与CRUD] ──> 第 3 周 [RAG核心攻坚] ──> 第 4 周 [前后端全量闭环] ──> 第 5 周 [压测答辩]
(成员A/B/C/D同频)     (接口契约冻结)           (SSE流式打字机跑通)      (教师后台与知识点解析)       (PPT制作与模拟演练)
```

- **第 1 周：技术准备与方案定型**
  - 【全体】明确 3 个典型课程场景（如《操作系统》、《计算机网络》），准备测试用 PDF/MD 文件。
  - 【成员 A】完成大模型 API 连通性测试与 LangChain4j 最小 Demo。
  - 【成员 B】完成 MySQL 数据库建表，并在 Postman 建立统一 Mock 空间。
  - 【成员 C & D】完成前端原型草图设计，确定统一组件库及设计规范。

- **第 2 周：骨架搭建与基础接口联调**
  - 【成员 A】实现文档解析引擎与分块切片算法。
  - 【成员 B】搭建 Spring Boot 基础工程，完成登录认证与课程 CRUD 接口。
  - 【成员 C】搭建 Vue3 基础工程，实现登录页、课程切换与侧边导航布局。
  - 【成员 D】搭建后台管理框架，实现课程管理页面与表格组件。

- **第 3 周：RAG 检索与智能答疑闭环（核心攻坚周）**
  - 【成员 A】完成向量库接入与 Top-K 相似度检索，封装 SSE 流式答疑接口。
  - 【成员 B】实现文件异步上传状态机与问答日志持久化。
  - 【成员 C】对接 SSE 接口，实现平滑打字机输出、Markdown 排版与出处展示。
  - 【成员 D】实现课件拖拽上传与解析进度动态展示。

- **第 4 周：知识点解析、教师后台与交互完善**
  - 【成员 A】开发基于知识库的考点精解与自测题生成接口。
  - 【成员 B】实现数据统计接口与教师纠偏保存逻辑。
  - 【成员 C】完成知识点卡片视图、答疑反馈与历史会话切换。
  - 【成员 D】完成教师问答审查表格与 ECharts 学情可视化看板。

- **第 5 周：端到端验收、文档封板与答辩准备**
  - 【全体】进行全链路功能集成联调与边界异常测试（防大模型超时、防并发卡顿）。
  - 【成员 C & D】UI 细节优化，添加加载占位骨架屏与空状态提示。
  - 【成员 D 牵头】完成系统设计说明书、使用手册录制及答辩演示 PPT。

## 五、 本科生答辩核心得分亮点

1. **真实可信的 RAG 溯源展示**：每条 AI 回答皆可展开命中课件页码及段落摘要，避免被评委质疑为“单纯套壳大模型”。
2. **极佳的答辩现场表现力**：支持流式打字机动效、代码高亮与公式渲染，告别白屏傻等。
3. **教师人工纠偏闭环**：当大模型出现幻觉时，教师可实时更正答案并沉淀为标准问答对，突出“工程可控性”。
4. **分工均衡且边界清晰**：2 后端 + 2 前端，代码仓提交规范，文档齐全，契合工程规范评价标准。
