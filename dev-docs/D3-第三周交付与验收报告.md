## 四、跨端链路验证（本轮新增）

**链路**：学生提问 → SSE 流式 → 后端落库 → 教师端问答记录可见。

| # | 步骤 | 实测结果 |
| :--- | :--- | :--- |
| 1 | 教师登录 | ✅ `code=200`，`role=TEACHER` |
| 2 | 上传对口课件 `第3章 内存管理.pdf` | ✅ `code=200`，docId=**10** → 轮询 1 次即 `CHUNKED`，**6 块** |
| 3 | 学生登录 | ✅ `code=200`，`role=STUDENT` |
| 4 | 学生发起 SSE 提问（`sessionId=0` 懒创建） | ✅ 三类事件齐全，详见下表 |
| 5 | **教师端记录可见** | ✅ `total=2`，出现 `id=2 / 提问「什么是虚拟内存分页机制？」` |
| 6 | 记录内容完整性 | ✅ 回答全文 + **4 条参考出处**（含 `fileName` / `chunkIndex` / `score`）+ `latencyMs=913` + `createdAt` |

**SSE 事件实测**：

| 事件 | 内容 |
| :--- | :--- |
| `event:references` | `[{"docId":10,"fileName":"第3章 内存管理.pdf","chunkIndex":5,"score":0.887, "snippet":"工作集模型用进程在最近一个时间窗口内访问过的页集合…"}]`（首包，检索命中） |
| `event:message` | 增量吐字 `{"delta":"按课件内容，虚拟内存分页"}` / `{"delta":"机制把进程的地址空间切成"}` … |
| `event:done` | `{"recordId":2,"sessionId":3,"finishReason":"stop","totalTokens":0}` |

> **结论**：跨端链路**结构正确、端到端可达**；检索命中相关度 0.887（阈值 0.70）。

### 4.1 本轮踩到的两个坑（供后续复现参考）

1. **`sessionId` 语义**：`SseChatController.java:89` 明确「传 `0` 或省略时懒创建新会话，续问传上次 `done` 包返回的 sessionId」。
   传**不存在的数字**会返回 `event:error {"message":"会话不存在","errorCode":404}`。
2. **`Chroma` 未启动时向量存内存**：`parse_status` 仍显示 `CHUNKED`、`chunkCount` 正常，但**重启后端后向量丢失** → 检索返回空 `references`。这是「最容易被误判为检索 Bug」的假象（B2 报告 §五-2 已记录，本次复核确认）。

## 八、复现方式（本机）

```bash
# 1. 起本地 Mock 大模型端点（无 AI Key 时）
#    ⚠️ 本机脚本（未入库）；他人等价：配置真实 AI_API_KEY 后无需本步
python -X utf8 项目/D/mock-llm/mock_llm.py 9999

# 2. 起后端并注入 Mock 端点
export AI_BASE_URL=http://127.0.0.1:9999/v1
export AI_API_KEY=mock-key
# ⚠️ 本机脚本（未入库）；他人等价：在 backend/ 目录执行 .\run-local.ps1
bash 项目/D/backend-start/start-backend.sh      # 改了 Java 代码加 -c

# 3. 起教师端前端
cd frontend-teacher && npm run dev

# 4. 跨端链路：先上传课件并等 CHUNKED，再以 sessionId=0 发起 SSE 提问
curl -N -H "Authorization: Bearer <学生 token>" \
  "http://127.0.0.1:8080/api/qa/chat/stream?courseId=1&sessionId=0&question=<urlencoded>"
```
