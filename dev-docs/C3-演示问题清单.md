# 学生端演示问题清单（成员 C / C3.3 交付物）

> 目的：保证 Gate 3 / 答辩当天「现场提问必有好效果」——每个问题都命中一个已知的知识点，
> 且能依次把学生端的前端能力完整亮一遍，不冷场、不空转。
> 问题来源：后端 `data.sql` 的 `course_knowledge_point` 种子数据（4 个知识点），
> 以及 3 门种子课程。**演示前请成员 A/D 确认这些知识点对应的课件 PDF 已上传并切块入库**，
> 否则 SSE 检索不到内容会触发「防幻觉拒答」，反而露怯。

| 步骤 | 操作 | 用什么问题 | 亮出什么能力 |
| :--- | :--- | :--- | :--- |
| 1 | 登录 `student01 / 123456` | — | 登录、路由守卫 |

## 二、好问题清单

> 每题都给出：为什么选它、预期答案要点、以及它命中的种子知识点。

### Q1 —— 必问，主链路全亮（课程 1：操作系统原理）

**问题**：`页面置换算法 LRU 和 FIFO 有什么区别？`

- **命中知识点**：`course_knowledge_point #2「页面置换算法 LRU 与 FIFO 对比」`
- **为什么好**：这是种子数据里 `qa_record` 演示记录就用过的问题，答案包含 **Markdown 表格**（算法/开销/Belady 异常对比）和**出处引用**（snippet 指向「第3章 内存管理.pdf」）。一个提问能同时演示：流式、Markdown 表格渲染、出处溯源、点赞。
- **预期效果**：答案含 `| 算法 | 实现开销 | Belady 异常 | 命中率 |` 表格；出处徽章显示 1+ 处引用。

### Q2 —— 展示代码块高亮（课程 1：操作系统原理）

**问题**：`用伪代码描述一下 LRU 页面置换算法的实现思路`

- **为什么好**：若课件/模型返回代码块，则演示 `MarkdownViewer` 的 **代码高亮 + 一键复制**（C2.2 的核心亮点）。若模型未返回代码，退路是 Q1 的表格已足够。
- **预期效果**：出现深色代码块，hover 出现「复制」按钮。

### Q3 —— 展示出处溯源的「多个引用」（课程 1）

**问题**：`进程和线程有什么区别？分别举例说明什么时候用多进程、什么时候用多线程`

- **命中知识点**：`course_knowledge_point #1「进程与线程的区别」`
- **为什么好**：答案偏概念辨析，适合展示**出处抽屉里多个引用卡片**的排版；也是知识点精解的绝佳触发点（知识点名 = 「进程与线程的区别」）。
- **预期效果**：出处徽章显示多处引用；点「知识点精解」能看到结构化 Markdown 精解。

### Q4 —— 换课不串答案（课程 2：计算机网络）

**问题**：`TCP 建立连接为什么是三次握手，断开为什么是四次挥手？`

- **命中知识点**：`course_knowledge_point #4「TCP 三次握手与四次挥手」`
- **为什么好**：这是演示 **courseId 隔离**的关键一问——在课程 2 下问，绝不该出现课程 1（操作系统）的内容；且答案是经典高频题，评委容易跟进。
- **预期效果**：答案只基于计算机网络课件；切换到本课程后侧栏历史会话刷新，不残留上一门课的会话。

### Q5 —— 防幻觉拒答（可选，展示严谨性）

**问题**：`请介绍一下量子计算的退相干机制`

- **为什么好**：与任何种子课件都无关，用于展示「课件中未找到相关内容」的**防幻觉拒答**（A2.2），体现 RAG 的可信边界。**只在演示时间充裕时用**，避免把评委注意力从核心功能引开。
