## 三、逐条验收证据

### B2.1 上传 + 状态机
```
POST /api/teacher/docs/upload  (courseId=1, file=第3章_内存管理_验收.md)
→ code=200, docId=6
落库即时状态  → parseStatus=PARSING
轮询 1.5s     → parseStatus=CHUNKED, chunkCount=1
filePath      → C:\Users\34677/smartqa/uploads/1/1789823370201_第3章_内存管理_验收.md（绝对路径，按 courseId 分目录）
```

### B2.2 校验与安全边界
| 用例 | 结果 |
| :--- | :--- |
| 上传 `evil.exe` | `code=400 仅支持 PDF / DOCX / MD / TXT 格式` |
| header 篡改文件名 `../../../../etc/passwd.md` | `code=400 文件名非法` |
| 空文件 | `code=400 上传文件不可为空` |
| 无 token | `code=401` |

### B2.3 问答记录持久化（SSE 全链路，核心）
```
GET /api/qa/chat/stream?courseId=1&question=虚拟内存的作用是什么？页面置换算法有哪些？&sessionId=0
→ event:references  [{"docId":6,"fileName":"第3章_内存管理_验收.md","chunkIndex":0,"score":0.9033,...}]
→ event:message × N  （流式累计 79 字）
→ event:done         {"recordId":5,"sessionId":6,"finishReason":"stop","totalTokens":168}
```
- 首包 `references` 命中刚上传的课件，`score=0.9033` → **检索 → 引用**链路通
- `done` 回传真实 `sessionId=6` → **懒创建（sessionId=0）生效**
- 续问「LRU 和 FIFO 有什么区别？」传 `sessionId=6`，返回仍为 `6` → **续问复用会话，不重复建会话**
- 查询会话明细可见 2 条记录，`question` 与提问逐字一致、`answer` 非空、`groundingReferences` 为 JSON 数组（长度 1）→ **出处快照落库**

### B2.4 会话列表 + 明细
- `GET /api/qa/sessions?courseId=1` → `code=200`，包含本次新建会话（该账号会话数 3）
- `GET /api/qa/records?sessionId=6` → `code=200`，2 条记录，按提问时间正序
- 负例：教师 token 读学生会话 → `code=403 无权查看他人会话`

### B2.5 教师端问答记录
- `GET /api/teacher/qa/records?courseId=1&pageNum=1&pageSize=10` → `code=200, total=3, pages=1`，本次记录可见
- 关键词搜索 `keyword=虚拟内存` → 命中 1 条且结果均与关键词相关
- 负例：学生 token → `403 无权访问该资源`；`courseId=999` → `404 课程不存在`；无 token → `401`

### B2.6 点赞 / 点踩
| 操作 | 结果 |
| :--- | :--- |
| `POST /api/qa/records/5/feedback {"status":1}` | `code=200 data=true`；回查 `feedbackRating=1` |
| 再 `{"status":-1}` | 回查 `feedbackRating=-1`（覆盖生效） |
| `{"status":0}` | `400 反馈状态只能是 1（点赞）或 -1（点踩）` |
| 他人（教师）对同一条记录点赞 | `403 只能评价自己的提问` |

> 测试后已把该记录 `feedbackRating` 还原为原值 0。

### B2.7 限流（服务重启后单账号冷启动连发）
```
第 1~20 次  HTTP=200 正常受理（SSE 首帧 event:references）
第 21 次     HTTP=200  body {"code":429,"message":"提问过于频繁，请稍后再试","data":null,"timestamp":...}
第 22/25 次  同样 429
未登录访问   code=401（非 500）
```
限流响应符合统一契约：**HTTP 状态仍为 200，业务码 429 在 body**，且为完整 `Result` 四字段。

## 五、已知限制与遗留

1. **本机无 `AI_API_KEY`**：真实大模型应答未经端到端验证（本次用本地 Mock 端点替代）。演示前需配置真实 Key，或按 A 的测试策略在 CI 中保持 Mock。
2. **Chroma 未起**：当前走 `InMemoryEmbeddingStore`，**重启后向量丢失但 `parse_status` 仍显示 `CHUNKED`**——这是最容易被误判为「检索 Bug」的假象，联调与演示前必须起 Chroma。
3. **`data.sql` 种子占位行**：`course_document id=1`（`/tmp/smartqa-demo/第1章_操作系统引论.pdf`，PENDING）会让前端 3 秒轮询永远停在"解析中"，且 reindex 必失败，建议删除。
4. 本次验收在 `course_document` 新增了 docId=6（验收用 md 课件），如不需保留可在演示前清理。
