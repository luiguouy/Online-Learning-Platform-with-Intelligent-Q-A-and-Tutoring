# 群规与站会速查卡（贴到群公告）

> 定位：微信群只做两件事——**转发链接**和**约时间**。所有状态、结论、讨论，账本在 GitHub。
> 详细规则见 `COLLABORATION_WORKFLOW.md` 第六、八节。

## 三条群规

1. **站会不发群里**。每天开工，在你正在做的任务 Issue 评论区发 3 行（模板见下），同时把卡片拖到看板对应列。
2. **四件事发生时，产生者负责把链接甩进群**（一行链接 + 一句人话，不复述内容）：
   - 我提了 PR（求 Review）
   - 有人 @ 我 / 我的 Issue 被指派、被打了 `blocked`
   - 契约变更 Issue 被创建或合并
   - P0/P1 缺陷 Issue 被创建（修复时限按小时计，等 GitHub 通知太慢，必须群里 @ 组长）
3. **群里拍板的结论，24 小时内由拍板人补录到对应 Issue**（决策是什么 / 为什么 / 牺牲了什么，3 句话）。

## 每日站会模板（发在任务 Issue 评论区）

```text
昨天：完成 XXX
今天：做 YYY
阻塞：无 / 阻塞：ZZZ 没好，我先用 ___ 顶着（已加 blocked 标签）
```

## 看板操作口诀

- 开工 → 卡片拖到 **In progress**
- 提 PR → 拖到 **Ready for review**，PR 链接发群
- CI 绿 + 1 人 Approve + 评论清完 → 合并（任务 Issue 自动关；缺陷 Issue 由发现者验证后手动关），卡片拖到 **Done**
- 卡住超 4 小时 → Issue 打 `blocked` 标签 + 群里 @ 组长

## 组长每日 30 秒检阅

打开看板按人过滤（`assignee:@luiguouy` 或按 `member-A/B/C/D` 标签过滤）：谁的列是空的、谁有 blocked、谁 3 天没动卡片——只追这三件事，不逐个问进度。
