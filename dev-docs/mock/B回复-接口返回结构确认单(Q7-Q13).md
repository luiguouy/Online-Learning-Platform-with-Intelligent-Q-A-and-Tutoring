## Q7 登录接口 `/api/auth/login` 的返回结构？token 怎么用？

**结论**：`Result<LoginVO>`，`data` 是**对象**，共 6 个字段；**本期无注册接口**。

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "token": "a1b2c3d4-...",   // Sa-Token 令牌
    "userId": 1,                // Long
    "username": "teacher01",
    "nickname": "李老师",
    "role": "TEACHER",          // STUDENT / TEACHER，前端路由守卫用
    "avatarUrl": ""
  },
  "timestamp": 1757692800000
}
```

**证据**：`AuthController.java:38-62`、`vo/LoginVO.java:23-44`

**前端动作**：
- `token` 存 `localStorage`，**键名 `satoken`**；
- 后续所有请求带 `Authorization: Bearer <token>`，**缺 `Bearer ` 前缀一律 401**（Sa-Token `token-prefix` 配置决定）；
- `el-upload` 有自己的通道、**不走 axios 拦截器**，必须手动补鉴权头（D 指南 4.1 已正确处理）。
- **不存在** `/api/auth/register`，别找。

## Q10 `groundingReferences` 返回的是 **JSON 数组** 还是 **JSON 字符串**？

**结论：JSON 数组（Array），不是字符串。** 你**不需要** `JSON.parse`。

```json
"groundingReferences": [
  {
    "docId": 12,
    "fileName": "第3章 内存管理.pdf",
    "chunkIndex": 14,
    "score": 0.88,
    "snippet": "虚拟内存分页机制中，页表存储了虚页号与物理页框号的映射关系……"
  }
]
```

**为什么是数组**：实体上两件事**同时**做了，缺一不可（`entity/QaRecord.java:40,76`）：
1. `@TableName(value = "qa_record", autoResultMap = true)`
2. `@TableField(value = "grounding_references", typeHandler = JacksonTypeHandler.class)`

Jackson 序列化后直接就是数组。元素结构 = `vo/SseReferenceVO.java`（`docId` / `fileName` / `chunkIndex` / `score` / `snippet`）。

**你的代码可以简化**：D 指南 4.2 里 `parseRefs()` 的 `typeof raw === 'string' → JSON.parse` 分支属于**防御性兜底**，现在**永远不会命中**。留着无害（不影响功能），但类型可以收紧成 `SseReference[]`：
```ts
const parseRefs = (raw?: SseReference[]): SseReference[] => raw ?? [];
```

**⚠️ 一个必须知道的边界**：`grounding_references` 列**允许 NULL 且历史数据可能为空数组**。
B 侧写入时保证非 null（`QaRecordServiceImpl.java:146` 兜底 `Collections.emptyList()`），但**种子数据 `data.sql` 里是合法 JSON 数组**，所以三种情况都要能渲染：`[]`、`null`、有值。你的 `raw ?? []` 已经覆盖。

## Q12 会话明细 `/api/qa/records?sessionId=` 返回结构与排序？

**结论：裸数组**，`Result<List<QaRecord>>`，按 `createdAt` **正序**（老→新）。

```json
{
  "code": 200, "message": "操作成功",
  "data": [
    {
      "id": 1, "sessionId": 1, "userId": 2, "courseId": 1,
      "question": "页面置换算法 LRU 和 FIFO 有什么区别？",
      "answer": "### 核心差异\n\n**FIFO** ……",    // Markdown 原文
      "groundingReferences": [ /* 见 Q10 */ ],

      "latencyMs": 1840,
      "isDeleted": 0,
      "createdAt": "2026-09-12T21:10:05"
    }
  ],
  "timestamp": 1757692800000
}
```

**证据**：`QaSessionController.java:46-50`、`service/impl/QaRecordServiceImpl.java:72-77`（`orderByAsc(createdAt)`）

**要点**：

- `answer` 是 **Markdown 原文**（可能含表格/代码块），必须走 Markdown 渲染管线；
- `id` 对应 SSE `done` 事件里的 `recordId`，前端拿它可以立刻发起 `feedback`；

## Q13 点赞/点踩 `POST /api/qa/records/{id}/feedback` 的请求体与返回？

**结论**：请求体字段名必须是 **`status`**，取值**只能是 `1` 或 `-1`**；返回 `Result<Boolean>`（`data: true`）。

**请求**
```http
POST /api/qa/records/1/feedback
Authorization: Bearer <token>
Content-Type: application/json

{ "status": 1 }      // 1=点赞，-1=点踩
```

**成功响应**
```json
{ "code": 200, "message": "操作成功", "data": true, "timestamp": 1757692800000 }
```

**证据**：`QaSessionController.java:52-58`、`dto/FeedbackDTO.java:19-26`、`service/impl/QaRecordServiceImpl.java:98-116`

**错误码对照（穷举，前端可直接按这个映射 Toast）**

| 触发条件 | code | message |
| :--- | :--- | :--- |
| `status` 为 `null`/`0`/`2` 等非 ±1 值 | `400` | `反馈状态只能是 1（点赞）或 -1（点踩）` |
| `status` 字段缺失 | `400` | `反馈状态不能为空`（Bean Validation） |
| `recordId` 不存在或已逻辑删除 | `404` | `问答记录不存在` |
| 评价**别人**的提问 | `403` | `只能评价自己的提问` |
| 未登录 / token 过期 | `401` | `登录已过期，请重新登录` |

**前端动作**：点完直接本地翻转按钮选中态即可，**不必重拉列表**（返回值只有 `true`，没有新记录对象）。
