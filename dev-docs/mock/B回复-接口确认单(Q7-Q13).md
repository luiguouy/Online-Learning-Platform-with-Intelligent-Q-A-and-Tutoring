**补充（关键，避免你误判状态）**：
- **落库即 `PARSING`，不会出现 `PENDING`**：代码在落库时直接写 `parseStatus = PARSING`（`TeacherDocumentController.java:100-108`），切块任务紧接着提交，不存在真正的排队期。所以你**上传后立刻拉 list 就能看到 `PARSING`**，直接开 3 秒轮询即可，不用等一个 `PENDING` 过渡。

- **大小上限 50MB**：超过会被全局异常处理器拦成 `400 文件超过 50MB 上限，请压缩后重试`（`application.yml:24` + `GlobalExceptionHandler`）。前端 `< 50MB` 校验先拦一道，后端再兜一道。
- **越权**：教师往非自己任课的课程传 → `403 无权操作该课程`（`TeacherDocumentController.java:73`）。
- **文件名安全**：含 `/` `\` `..` 直接报 `400 文件名非法`（`:84-86`）——正常文件不会触发，但如果你的上传组件会拼接路径，注意别把目录带进来。

**白送你的字段**：`pages`（总页数）**已经算好返回了**，前端 `el-pagination` 的 `:page-count` 可以直接用 `res.pages`，**不用自己 `Math.ceil(total/pageSize)`**。

**请求参数**（`TeacherQaController.java:37-40`）：
| 参数 | 必填 | 默认 | 说明 |
| :--- | :--- | :--- | :--- |
| `courseId` | ✅ | — | 越权校验：非自己任课 → `403 无权操作该课程` |
| `pageNum` | ❌ | `1` | 小于 1 会被规整成 1 |
| `pageSize` | ❌ | `10` | **上限 100**，传 1000 会被压到 100 |
| `keyword` | ❌ | 无 | 模糊匹配 **`question` 或 `answer`**（两边都搜） |

排序：`createdAt` **倒序**（最新提问在最上，`QaRecordServiceImpl.java:88`）。

---

**结论二：`groundingReferences` 返回的是 JSON 数组，不是字符串。** 你**不需要** `JSON.parse`。

```json
"groundingReferences": [
  {
    "docId": 12,
    "fileName": "第3章 内存管理.pdf",
    "chunkIndex": 14,
    "score": 0.88,
    "snippet": "虚拟内存分页机制中，页表存储了虚页号与物理页框号的映射关系……"
  }
]
```

**为什么是数组**：实体上两件事**同时**做了，缺一不可（`entity/QaRecord.java:40,76-78`）：
1. `@TableName(value = "qa_record", autoResultMap = true)`；
2. `@TableField(value = "grounding_references", typeHandler = JacksonTypeHandler.class)`，字段 Java 类型是 `List<SseReferenceVO>`。

元素结构 = `vo/SseReferenceVO.java:35-48`，**五字段冻结**：`docId` / `fileName` / `chunkIndex` / `score` / `snippet`。

**你的处理怎么改**（对应你说的"标为主路径还是兼容保护"）：
- `typeof raw === 'string' → JSON.parse` 分支 → 标记为 **「兼容保护」**（`autoResultMap` 已在位，此分支**永远不会命中**）。
- `Array.isArray(raw) → 直接用` 分支 → 标记为 **主路径**。
- 类型可以收紧：
  ```ts
  // 建议：主路径收紧，兜底保留
  const parseRefs = (raw?: SseReference[] | null): SseReference[] =>
    Array.isArray(raw) ? raw : [];
  ```

**⚠️ 一个边界必须兼容**：`grounding_references` 列 DDL 允许 NULL。B 侧写入时已兜底 `Collections.emptyList()`（`QaRecordServiceImpl.java:146`），**新数据不会是 null**；但**历史/种子数据可能是 `null` 或 `[]`**。三种情况（`null` / `[]` / 有值）都要能渲染——你的 `raw ?? []` 已覆盖，保留即可。

## 附二 · 我这边记账的技术债（不影响你，知道就行）

1. **`filePath` 暴露**：课件列表把服务器绝对路径返回给前端了。要干净可加 `@JsonIgnore`，但那是**响应结构变更**，得走四步法，第 1 周先不动。
2. **两个同名 `QaSessionService` 并存**：`service/rag/QaSessionService`（A 的内存占位实现）与 `service/QaSessionService`（B 的持久化接口）。当前 SSE 链路注入的是 A 的占位版，等 A 第二周切过来才算真正接上持久化——**对你（教师端问答记录页）无影响**，记录页读的是 `qa_record` 表，B 侧已就绪。
3. **`grounding_references` 历史 null**：老数据可能为 null，前端兼容即可（已在 Q10 说明）。

## 附三 · 契约里我不会单方面改的东西（改必走四步法）

1. **路径逐字符**：`TEAM_WORK_DIVISION.md` 接口矩阵那 12 条路径已冻结，前端写死，改一个字符就 404。
2. **统一响应体**：永远是 `{code, message, data, timestamp}`，`code ∈ {200,400,401,403,404,429,500}`。
3. **状态机四态**：`PENDING` / `PARSING` / `CHUNKED` / `FAILED`，**命名冻结，禁止别名**。
4. **`SseReferenceVO` 五字段**：`docId` / `fileName` / `chunkIndex` / `score` / `snippet`，SSE references 事件与 `qa_record` 快照**共用同一结构**。
5. **给 A 的两个冻结方法**（Day 3 死线）：
   - `QaRecordService.saveStreamingRecord(courseId, sessionId, question, answer, references, latencyMs)` → 返回 `recordId`（不可为 null）；
   - `QaSessionService.createSessionLazy(courseId, question)` → 返回 `sessionId`（不可为 null）。
   - 异步线程改用 `saveStreamingRecordAs(userId, ...)` 与 `createSessionLazyForUser(userId, ...)`。
