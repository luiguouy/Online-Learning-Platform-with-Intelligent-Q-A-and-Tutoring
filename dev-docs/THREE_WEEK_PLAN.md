# 三周冲刺计划：每人每周任务与验收标准（v2.0 · 工期与范围权威文件）

> **本文件是工期与功能范围的唯一权威**。`TEAM_WORK_DIVISION.md` 第四章的原 5 周路线图已作废。
> **总工期**：21 天。**有效工时估算**：每人每周约 15 小时（上课日 2h × 5 + 周末 5h）。
> **核心策略**：**并行开发 + Mock 解耦 + 每周一个硬门禁**。不做"后端写完前端再开始"的串行瀑布——3 周工期下瀑布必死。

---

## 一、 功能范围（已冻结，不得扩张）

**本期只实现以下 5 项功能，一项不多做。** 组员与 AI Agent 均不得自行添加功能——每多一个功能，就少一分按时交付的把握。

| # | 功能 | 包含内容 | 不包含 |
| :--- | :--- | :--- | :--- |
| 1 | **课程资料构建 RAG 知识库** | 课件上传、课件列表、课件删除（级联删向量）、重新构建索引、解析切块、向量化入 Chroma、`courseId` 隔离检索 | MinIO 分布式存储、多格式冷门文档、OCR |
| 2 | **学生提问智能答疑** | SSE 流式问答、参考资料出处溯源、无资料时拒答（防幻觉） | 多轮对话记忆、语音输入、图片提问 |
| 3 | **知识点解析** | 按知识点生成精解（核心概念 + 难点辨析），Markdown 展示 | **自测题/答题交互**、掌握度评估 |
| 4 | **问答记录** | 会话懒创建、问答持久化、历史会话与明细查询、**点赞/点踩** | 导出、分享 |
| 5 | **教师后台管理** | 课件管理（上传/删除/状态监控/重建索引）、**问答记录查看（只读）** | **人工纠偏（已裁掉）**、**ECharts 学情看板（已裁掉）**、统计报表 |

**已明确裁掉的功能（不要再实现、不要写进文档）**：人工纠偏、学情统计接口与图表看板、知识点自测题、金标集与 recall 评测脚本、演示缓存回放与录屏预案。

**范围外但保留的两项（防刷与体验，成本极低）**：接口限流、点赞/点踩。

### 1.1 接口清单（12 个，唯一真源见 `TEAM_WORK_DIVISION.md` 第三章）

```text
认证与课程：POST /api/auth/login          GET  /api/course/list
课件管理：  POST /api/teacher/docs/upload  GET  /api/teacher/docs/list
            DELETE /api/teacher/docs/{id}  POST /api/teacher/docs/{id}/reindex
智能答疑：  GET  /api/qa/chat/stream (SSE)
问答记录：  GET  /api/qa/sessions          GET  /api/qa/records
            POST /api/qa/records/{id}/feedback
知识点解析：POST /api/knowledge/generate
教师查看记录：GET /api/teacher/qa/records
```

### 1.2 三个必须先接受的现实

1. **零经验 + AI 生成代码**，约 30% 时间花在修编译错误。任何"看起来 2 小时"的任务，按 1.5 倍估算。
2. **RAG 是全项目唯一的技术深水区**（解析、切块、向量化、检索、流式），风险集中在成员 A 一人身上。**A 是单点故障，必须最先启动、最先验证**。
3. **3 周做不完"完整的企业级系统"**。接受"能用、能演示、能讲清楚"的标准，不要追求完美。

## 七、 时间不够时的裁剪顺序（从下往上砍）

**首先明确：第 1 节的 5 项核心功能一项都不能砍**——那是交付物本身。时间不够时，只能砍下面这些附属项：

1. 重建索引（reindex）功能——用"删除课件 + 重新上传"人工替代
2. 点赞/点踩——保留数据库字段但暂不做前端交互
3. 历史会话切换——保留记录持久化，前端只显示当前会话
4. 接口限流——演示现场人工控制提问频率
5. UI 打磨（骨架屏、动画）——功能可用即可

**判断依据**：宁可"5 项功能都完整、界面朴素"，也不要"10 个半成品功能"。评委问的是"你的 RAG 怎么工作的"，不是"你有几个图表"。
