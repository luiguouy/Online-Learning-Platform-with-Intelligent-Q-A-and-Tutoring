## 二、 成员细粒度分工计划清单 (WBS)

### 2.1 成员 A（组长 / AI 与 RAG 核心架构师）
- **核心任务**：
  1. **工程骨架搭建**：创建 Spring Boot 3.x 统一工程，集成 Maven 依赖管理，制定代码分支规范。
  2. **RAG 向量流水线**：
     - 基于 LangChain4j 或 Spring AI，封装课件文档提取解析器（支持 PDF、Markdown、TXT）。
     - 实现智能文本切块逻辑（Recursive Chunking: 400 字符分块，50 字符重叠）。
     - 集成 Text Embedding 模型（采用本地轻量量化向量模型 BGE-Small-ZH，零成本离线计算）。
     - 接入轻量向量库（Chroma Docker 单机版 或 LangChain4j 内置向量存储）。
  3. **智能答疑检索增强**：
     - 实现根据 `courseId` 元数据过滤的 Top-K 向量相似度检索。
     - 设计专业学科助教 Prompt 模板（注入上下文、防幻觉、严格格式约束）。
     - 编写 Server-Sent Events (SSE) 流式返回控制器 `/api/qa/chat/stream`。
  4. **知识点深度解析生成**：
     - 编写结构化 Prompt，生成指定知识点的核心概念与难点解析。

### 2.2 成员 B（后端业务与数据库工程师）
- **核心任务**：
  1. **数据库模型设计**：
     - 设计并编写 MySQL 建表脚本：`sys_user`（用户表）、`course`（课程表）、`course_document`（课件文档表）、`qa_session`（问答会话表）、`qa_record`（问答明细表）、`course_knowledge_point`（知识点表）。
  2. **基础业务代码开发**：
     - 基于 MyBatis-Plus 实现通用 BaseMapper、IService 及 CRUD 接口。
     - 集成 Sa-Token 轻量级权限框架，实现学生与教师的角色鉴权与 Token 校验。
  3. **课程与文件元数据管理**：
     - 实现本地文件上传接口（**严禁引入 MinIO**），校验文件大小与扩展名、清洗文件名防路径穿越。
     - 维护文档处理状态机：`PENDING(排队中)` -> `PARSING(切块中)` -> `CHUNKED(已就绪)` -> `FAILED(失败)`（四态命名冻结，禁止别名）。
  4. **问答历史与评价系统**：
     - 实现问答记录的异步持久化（记录学生提问、模型答案、知识库出处 JSON 片段）。
     - 实现学生点赞/点踩反馈接口、历史会话分页查询。
     - 提供教师后台问答记录查询接口（按课程 / 时间 / 关键词筛选，**只读**）。

### 2.3 成员 C（前端开发工程师 - 学生交互核心）
- **核心任务**：
  1. **学生前台界面架构**：
     - 搭建 Vue 3 + Vite + Element Plus + Pinia 前端基础脚手架。
     - 配置前端路由系统与全局状态（当前选中的课程、当前对话 Session）。
  2. **核心流式问答工作台**：
     - 对接后端 SSE 接口，实现打字机平滑流式吐字动画与光标闪烁效果。
     - 集成 Markdown 解析库（支持标准 Markdown 语法、表格、任务列表）。
     - 集成 `highlight.js` 实现代码高亮与一键复制功能。
  3. **知识溯源抽屉 (Grounding Drawer)**：
     - 回答气泡底部渲染“参考资料 (X 处)”标签。
     - 点击弹窗或右侧抽屉，展示命中的课件片段详情（包含课件名、分块序号及相关度得分）。
  4. **知识点解析展示**：
     - 展示知识点精解内容（Markdown 渲染），**不做自测题交互**。

### 2.4 成员 D（前端开发与质检工程师 - 教师后台与文档）
- **核心任务**：
  1. **教师后台管理工作台**：
     - 实现课程列表展示与当前课程切换（**只读**；课程的新增/编辑不在本期范围内）。
     - 实现课件知识库管理界面（拖拽上传课件、查看解析切块进度条、手动重新构建索引）。
  2. **问答记录查看**：
     - 开发学生提问日志表格，支持按课程、时间、关键词筛选。
     - 支持查看单条问答的完整内容（提问、AI 回答、参考出处）。
  3. **全链路测试与答辩成果物**：
     - 负责 Postman / 前后端端到端黑盒测试，记录 Bug 缺陷清单并推动修复。
     - 准备高质量测试课件数据集（如精选 3~5 篇经典计算机教材章节 PDF）。
     - 编写《软件需求规格说明书》、《系统详细设计文档》及最终答辩汇报演示 PPT。

## 三、 前后端与 AI 协同接口矩阵 (API Matrix)

| 接口名称 | 接口路径 | 请求方式 | 提供方 (责任人) | 调用方 (责任人) | 核心联动数据 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **用户登录** | `/api/auth/login` | `POST` | 成员 B | 成员 C & D | 账号密码 -> Token & Role |
| **课程列表** | `/api/course/list` | `GET` | 成员 B | 成员 C & D | 课程列表与激活状态 |
| **课件上传** | `/api/teacher/docs/upload` | `POST (Form)` | 成员 B & A | 成员 D | 上传课件并触发异步切块 |
| **课件列表** | `/api/teacher/docs/list?courseId=` | `GET` | 成员 B | 成员 D | 教师端课件管理列表（实现见 B 指南 4.5） |
| **课件删除** | `/api/teacher/docs/{id}` | `DELETE` | 成员 B（接口）+ 成员 A（删向量） | 成员 D | 级联清理 Chroma 切块，防幽灵参考 |
| **索引重构** | `/api/teacher/docs/{id}/reindex` | `POST` | 成员 B（接口）+ 成员 A（重建向量） | 成员 D | 重新计算 Embedding 向量，异步执行 |
| **智能答疑 (SSE)** | `/api/qa/chat/stream` | `GET (SSE)` | 成员 A | 成员 C | `question`, `courseId` -> 流式片段与出处 |
| **会话历史** | `/api/qa/sessions?courseId=` | `GET` | 成员 B | 成员 C | 历史会话列表（实现见 B 指南 4.5） |
| **会话明细** | `/api/qa/records?sessionId=` | `GET` | 成员 B | 成员 C | 指定会话下的问答记录（实现见 B 指南 4.5） |
| **点赞评价** | `/api/qa/records/{id}/feedback`| `POST` | 成员 B | 成员 C | `recordId`, `status(1/-1)`（实现见 B 指南 4.5） |
| **知识点生成** | `/api/knowledge/generate` | `POST` | 成员 A | 成员 C | 知识点名称 -> 结构化考点解析 |
| **教师查看问答记录** | `/api/teacher/qa/records?courseId=` | `GET` | 成员 B | 成员 D | 学生提问明细，供教师后台查看 |

> **Mock 先行**：接口未实现前，提供方先给 Postman Mock 或 Knife4j 定义，调用方照 Mock 开发，互不阻塞（同上 6.4）。

## 五、 本科生答辩核心得分亮点

1. **真实可信的 RAG 溯源展示**：每条 AI 回答皆可展开命中课件页码及段落摘要，避免被评委质疑为“单纯套壳大模型”。
2. **极佳的答辩现场表现力**：支持流式打字机动效、代码高亮渲染，告别白屏傻等。
3. **知识库可治理**：教师可随时上传、删除课件并重建索引，AI 回答随课程资料变化即时更新——证明答案是"从课件里找出来的"而不是模型凭空编的。
4. **分工均衡且边界清晰**：2 后端 + 2 前端，代码仓提交规范，文档齐全，契合工程规范评价标准。
